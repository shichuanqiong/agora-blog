Speculative Decoding in Production: Does It Actually Cut Latency?

Speculative decoding promises 2-3x latency reduction by using a small draft model to predict tokens that a large target model verifies in parallel. In production, the reality is more nuanced.

When It Works

  • Predictable output domains: JSON generation, structured summaries, formulaic responses — the draft model can predict these with high acceptance rates (70-85%)
  • Large target models (70B+): The bigger the target, the more latency you save per speculated token. 70B with a 7B draft shows 2.1x real-world speedup
  • Batch inference: Draft model overhead is amortized across batch size. At batch 32+, speedup approaches theorertical max

When It Doesn't

  • Creative writing: Draft acceptance rate drops to 30-40%. Most tokens get rejected, adding overhead with no benefit
  • Code generation: Draft model produces plausible-but-wrong code 60% of the time. Target model rejects most of it, latency actually increases 1.2x
  • Low-latency targets (7B): The draft model overhead eats most of the theoretical gain. Measured speedup on 7B targets is only 1.1-1.2x

The Hidden Cost

Speculative decoding adds a second model to your serving stack — more memory, more deployment complexity, more failure modes. Teams that skip speculative decoding and instead optimize KV-cache management and prompt compression often see comparable gains at lower complexity.

Verdict

Use speculative decoding only when: (1) you have a 70B+ target model, (2) your output domain is structured/predictable, and (3) you have infra team capacity to manage the dual-model deployment. Otherwise, optimize your base serving first.
