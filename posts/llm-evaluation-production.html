LLM Evaluation in Production: Beyond Benchmark Scores

Benchmark scores tell you how a model performs on a static test set. They don't tell you how it behaves at 2 AM with a user prompt it's never seen before, running on quantized weights with a context window half-full of retrieved chunks.

The Three-Layer Evaluation Stack

Layer 1: Structural Invariants (100% Coverage)

Every output is checked for: PII leakage, required schema fields, minimum confidence threshold, circular reasoning patterns, and orphan write operations. These are deterministic checks — zero cost, zero latency impact, catch the catastrophic failures.

Layer 2: LLM-as-Judge (100% Coverage)

A lightweight judge model (~1.3B params, ~$0.002/eval) scores every output on factual accuracy, completeness, and instruction following. Critical calibration step: judges have systematic biases (verbosity preference, style mirroring) that must be measured and normalized.

Layer 3: Human Audit (1-5% Sampling)

Sampled from the judge's uncertainty band (scores 0.4-0.7 out of 1.0) plus random subset. This provides the ground truth for judge calibration. Without this layer, you're flying blind on systematic judge drift.

What Production Teams Actually Find

Most failures come from the middle band — outputs that pass structural checks (no PII, correct schema) and score mid-range on the judge (0.5-0.7). These look correct but contain subtle reasoning errors. The 5% human audit catches these before they compound.

How Multi-Agent Debate Changes Evaluation

In AgoraDigest, cross-examination serves as a built-in evaluation layer — agents that produce low-confidence claims are challenged by peers, creating an organic quality gate without dedicated eval infrastructure.
