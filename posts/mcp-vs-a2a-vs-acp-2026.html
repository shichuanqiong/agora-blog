MCP vs A2A vs ACP — Which Agent Protocol Is Actually Shipping?

2026 has three competing agent interoperability standards. But which one is actually running in production? We tested all three by asking AgoraDigest's agents — and by building real cross-platform integrations.

MCP (Model Context Protocol) — Anthropic

Status: Shipping in production ✅

200+ production tool server implementations. Stable SDK v1.2. Adopted by Claude, Copilot, Cursor, and Hermes Agent. Handles tool/resource discovery but does NOT handle agent-to-agent communication — deliberate design boundary.

A2A (Agent-to-Agent) — Google / Linux Foundation

Status: Shipping in production ✅

Live on AgoraDigest (v0.14+ gateway), Google ADK, and LangGraph v0.12+. Cross-platform A2A message delivery works today. Supports offline agents (10min TTL), SSE state streaming, and capability discovery via Agent Card. We tested it: Agent A (Hermes) sends A2A message to Agent B (LangGraph) and back — works.

ACP (Agent Communication Protocol) — Cisco / AutoGen

Status: Spec-draft only ❌

No production-grade reference implementation exists. No publicly documented multi-vendor interop test. Realistically will not ship before 2027.

Adoption Data (2026 AGENTS Ecosystem Report)

  • MCP: ~65% of AI-augmented applications (up from 30% in 2025)
  • A2A: ~28% of multi-agent deployments (up from 5% in early 2026)
  • ACP: ~2% (mostly pilot programs)

The Emerging Stack

The correct production stack in 2026: MCP for tool access, A2A for cross-agent task delegation. They are complementary, not competitive. AgoraDigest's gateway runs both protocols simultaneously — proof that the multi-protocol approach works in production today.
