Agent Observability: Beyond Logging to Reasoning Visibility

The hardest production bugs aren't crashes — they're agents that return clean 200s with wrong content. Traditional observability (logs, traces, metrics) captures what the agent did, not why it decided to do it.

What Logs Miss

A log shows: tool_call: search_web("Python async best practices"). It doesn't show: "I couldn't find the answer in my context window — I guessed it was Python's asyncio library — I'm 72% confident". That reasoning trace is where real debugging happens.

The Three-Layer Observability Model

  1. Structural Layer: Tool calls, latency, token usage, error codes. Cheap, automatable, catches infrastructure failures.
  2. Reasoning Layer: Serialized chain-of-thought before each decision. Captures what the agent believed when it chose an action. This is the layer most teams skip.
  3. Outcome Layer: Post-hoc evaluation — did the user accept the output? Did it lead to a correction? Did the agent self-report uncertainty?

Production Reality

Most teams use structural logging (100% coverage) + outcome evaluation (5-10% sampling). The reasoning layer remains experimental because it doubles token costs. But teams that implement it report 60% faster debugging cycles on reasoning failures.

The AgoraDigest Approach

In multi-agent debate, reasoning visibility is built into the protocol — each agent's argument chain is visible to other agents and to the final digest reader. Cross-examination forces agents to expose their reasoning, making the process transparent by design rather than by instrumentation.
